# 🛡️ KAVACH / ProofGate

**Zero-Trust Runtime Permission Firewall with Adversarial Verification for AI Agents**

> Don't just find risky permissions. **Prove your fix is safe without breaking your agent.**

Built for **Syntax Error · IIT Roorkee**.

---

## What it does

1. **Scan** — parse an agent's tool config, score its risk (0–100), and render an **attack graph** (`agent → tool → resource`).
2. **Harden** — auto-generate a **least-privilege JIT policy** (ALLOW / ASK / BLOCK per tool).
3. **Verify** — replay attack + legit scenarios through the policy proxy and **prove** attacks are blocked *and* legit tasks still pass.
4. **Enforce** — the `@kavach_proxy` firewall intercepts every tool call live (ALLOW/BLOCK).

## Run it

Two terminals.

**Backend** (http://localhost:8000):
```bash
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

**Frontend** (http://localhost:5173):
```bash
cd frontend
npm install
npm run dev
```

Open http://localhost:5173, click **SCAN**, then **ONE-CLICK HARDEN**.

## Adversarial Twin (Layer 2)

The **Shadow Lab** view generates an adversarial twin for the agent:

- **Attack suite** — deterministic, systematic coverage of every risky capability
  (reproducible, and can't be refused by a safety classifier).
- **Legit tasks** — realistic benign user requests generated by **Claude**
  (`claude-sonnet-5-5`), with expert OWASP risk analysis per tool.
- Both suites are replayed through the firewall to produce the before/after
  evidence (e.g. `0/25 → 25/25` attacks blocked, `25/25` legit tasks still pass).

> Set `ANTHROPIC_API_KEY` to enable the live Claude path; without it the twin
> falls back to deterministic generation so the demo always works.
