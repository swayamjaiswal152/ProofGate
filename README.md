# 🛡️ ProofGate

**Zero-Trust Runtime Permission Firewall with Adversarial Verification for AI Agents**

> Don't just find risky permissions. **Prove your fix is safe without breaking your agent.**

**🔗 Live demo:** **https://proof-gate-beryl.vercel.app** &nbsp;·&nbsp; API: https://proofgate-api-fr7y.onrender.com
**📄 Example blocked PR:** [PR #1](https://github.com/swayamjaiswal152/ProofGate/pull/1) — the CI gate blocking an over-permissioned agent.

> The live demo runs in safe fallback mode (no API key). The backend sleeps after
> inactivity — the first load may take ~50s to wake, then it's instant.

---

## What it does

1. **Scan** — parse an agent's tool config, score its risk (0–100), and render an **attack graph** (`agent → tool → resource`).
2. **Harden** — auto-generate a **least-privilege JIT policy** (ALLOW / ASK / BLOCK per tool).
3. **Verify** — replay attack + legit scenarios through the policy proxy and **prove** attacks are blocked *and* legit tasks still pass.
4. **Enforce** — the `@proofgate_proxy` firewall intercepts every tool call live (ALLOW/BLOCK).

## Run it

Two terminals.

**Backend** (http://localhost:8000):
```bash
cd backend
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

**Frontend** (http://localhost:5173):
```bash
cd frontend
npm install
npm run dev
```

Open http://localhost:5173, click **SCAN**, then **ONE-CLICK HARDEN**.

> `localhost` only works on the machine running the servers. For a link anyone can open,
> see **Deploy** below.

## Deploy (live, free)

Two pieces: backend on **Render**, frontend on **Vercel**. Runs in safe fallback mode by
default (no API key = deterministic twin, no cost); the demo looks identical.

**1. Backend → Render**
- New → **Blueprint** → connect this repo. It reads `render.yaml` (root dir `backend`,
  start `uvicorn app.main:app --host 0.0.0.0 --port $PORT`).
- Copy the deployed URL, e.g. `https://proofgate-api.onrender.com`.
- _(Optional)_ Add `ANTHROPIC_API_KEY` in the dashboard to enable live Claude.

**2. Frontend → Vercel**
- New Project → import this repo → **Root Directory = `frontend`** (framework: Vite, auto).
- Add env var **`VITE_API`** = your Render backend URL (from step 1).
- Deploy. The resulting URL is your live demo link.

> Render's free tier sleeps after inactivity — the first request may take ~50s to wake.
> Hit the backend URL once before demoing.

## Adversarial Twin (Layer 2)

The **Shadow Lab** view generates an adversarial twin for the agent:

- **Attack suite** — deterministic, systematic coverage of every risky capability
  (reproducible, and can't be refused by a safety classifier).
- **Legit tasks** — realistic benign user requests generated by **Claude**
  (`claude-sonnet-5-5`), with expert OWASP risk analysis per tool.
- Both suites are replayed through the firewall to produce the before/after
  evidence (e.g. `0/25 → 25/25` attacks blocked, `25/25` legit tasks still pass).

> Set `ANTHROPIC_API_KEY` to enable the live Claude path; without it the twin
> falls back to deterministic generation so the demo always works.

## Evidence Ledger (Layer 4)

After a Shadow Lab run, **📄 Evidence Report** renders a print-ready enterprise audit
report (risk before/after, attack matrix, enforced policy, SOC2/GDPR/HIPAA mapping, and a
SHA-256 integrity hash). Browser → Save as PDF produces the downloadable artifact.

## CI/CD Gate

The same engine runs as a pull-request gate — a PR that ships an over-permissioned agent
**fails the check**:

```bash
cd backend
python -m app.cli scan examples/support_agent.yaml --max-risk 30   # exits 1 (BLOCKED)
python -m app.cli scan examples/support_agent_hardened.yaml        # exits 0 (PASSED)
```

Flags: `--max-risk <0-100>` sets the gate threshold (default 30); `--md <path>` writes a
markdown report for posting as a PR comment.

### Auto-comment on pull requests

Wired as a GitHub Action in `.github/workflows/proofgate.yml`. On every pull request the
Action:

1. Scans the agent config and computes its risk + attack paths.
2. **Posts the full security report as a PR comment** (like CodeQL / Snyk / SonarCloud) —
   risk score, attacks blocked before/after hardening, and an OWASP-mapped attack-path table.
3. **Blocks the merge** (fails the check) when risk exceeds the threshold.

The report step runs even when the gate fails (`continue-on-error` on the scan, enforced in a
later step), so the comment is always posted. Posting requires `permissions: pull-requests:
write`, and the comment is rendered by `app.cli --md` + `gh pr comment`.

Point the Action at your own agent by setting the `AGENT_CONFIG` / `MAX_RISK` env in the
workflow. It ships pointed at the deliberately-vulnerable example so the gate visibly fails.

Example PR comment:

> ## ❌ ProofGate Security Gate — FAILED (merge blocked)
> **Agent:** `acme-support-agent` · **Tools:** 7
>
> | Metric | Value |
> | --- | --- |
> | Risk score | **90/100** (CRITICAL) |
> | Attacks blocked (after ProofGate hardening) | **10/10** |
> | Legit tasks still passing | 10/10 |
>
> 🔴 Attack paths: Remote Code Execution, Secret Exfiltration, Data Destruction, Financial Fraud
